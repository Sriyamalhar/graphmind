# ADR 001: Frame the task as shortest-path distance regression, not classification

## Status
Accepted

## Context
A GNN applied to graphs can be pointed at many tasks: node classification,
link prediction, graph classification, or regression. GraphMind needed a
task that (a) has an unambiguous, cheap-to-generate ground truth, and
(b) admits a direct, fair comparison against a classical algorithm already
implemented in this ecosystem (Dijkstra/A* in the Meridian project).

## Decision
Frame the task as: given a graph and a (source, target) node pair, predict
the shortest-path distance between them. Ground truth is generated by a
hand-implemented Dijkstra (see `src/graphmind/data/classical_algorithms.py`),
run once per unique source node per sampled batch of pairs.

## Alternatives considered
- **Node classification** (e.g. "is this node a congestion hotspot"): rejected
  because it requires either real traffic data (not available) or synthetic
  labels invented without a principled generation process, which weakens the
  benchmark's credibility.
- **Link prediction** (e.g. "which edges will see high traffic"): rejected for
  the same reason, and because it does not have a natural classical-algorithm
  baseline to benchmark against, which was the whole point of this project.

## Consequences
- The benchmark story is clean: Dijkstra's answer is provably correct, so
  the GNN's error is measured against ground truth, not proxy labels.
- The tradeoff being measured is genuinely interesting: batched GNN inference
  vs. per-pair classical search, on both accuracy and wall-clock/memory cost.
- Limitation: this is a transductive setting (same graph across train/val/test
  splits, different query pairs). Generalization to unseen graphs is a
  separate, harder problem, tracked as a stretch goal (see BENCHMARK.md,
  "Future work").
